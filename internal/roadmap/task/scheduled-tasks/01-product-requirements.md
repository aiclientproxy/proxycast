# 已安排任务产品需求合同

状态：`normative / requirements-ready`

## 1. 产品定义

“已安排任务”是由用户预先定义、按日程触发的 Agent 工作。每次触发都产生一个可追溯的真实运行，并在需要时创建或继续一个 canonical Thread。它不是系统 Cron 管理器，也不是后台脚本列表。

## 2. 用户与核心诉求

| 用户                       | 核心诉求                                         |
| -------------------------- | ------------------------------------------------ |
| 高频使用 Lime 的个人开发者 | 把已经跑通的对话工作交给 Lime 定期执行           |
| 项目负责人                 | 固定项目、模型、权限和工作目录，避免每次重复配置 |
| 需要监控/汇总的用户        | 快速确认是否运行、下次何时、最近结果是否需要处理 |

## 3. 核心用户故事

### 创建

- 作为用户，我可以点击“创建 -> 使用 Lime 创建”，在新对话中自然语言描述任务和运行时间。
- 作为用户，我可以点击“创建 -> 手动设置”，直接填写结构化表单。
- 作为用户，我可以在当前对话中要求“把这件事每天运行”，并在创建前看到结构化摘要与确认动作。
- 作为用户，我可以基于当前对话创建任务，保留上下文来源，但之后每次运行默认进入独立运行 Thread，避免污染原对话。

### 管理

- 我可以搜索任务，并按全部、已启用、已暂停筛选。
- 我可以看到任务名称、日程、运行状态、下一次运行和是否需要处理。
- 我可以打开任务详情，编辑指令、运行上下文、日程、通知与启用状态。
- 我可以暂停、恢复、立即运行或删除任务。

### 运行与追溯

- 每次运行都能打开对应对话，查看完整 Turn/Item、工具调用、审批与结果。
- 运行中、成功、失败、超时和等待人工处理都可区分。
- 失败后我能看到原因和恢复路径；暂停不会删除历史。

## 4. 信息架构

侧边栏一级导航：

```text
新对话
已安排任务
插件
...
```

已安排任务内部：

```text
目录列表
  -> 任务详情
      -> 基本信息
      -> 运行上下文
      -> 频率
      -> 运行历史
      -> 更多操作
```

设置页只保留系统级诊断或总开关，不再复制任务目录和编辑工作台。

## 5. P0 功能范围

### 5.1 目录

- 搜索：匹配名称和 prompt 摘要；前端即时过滤，服务端分页留在数据合同中。
- 筛选：全部、已启用、已暂停。
- 列表摘要：名称、自然语言日程、最近/当前状态。
- 建议模板：每日简报、每周回顾、跟进监控；只预填表单，不创建特殊 runtime 类型。
- 空态：说明没有匹配任务，并提供创建动作。

### 5.2 创建菜单

- “使用 Lime 创建”：打开新 Thread，注入任务创建 intent；Agent 产出结构化 draft，用户确认后才调用 create。
- “手动设置”：打开详情编辑面板，默认启用；未通过校验时创建按钮禁用并显示原因。

### 5.3 任务字段

| 区块 | 字段          | P0 要求                                                       |
| ---- | ------------- | ------------------------------------------------------------- |
| 基本 | 标题          | 必填，1-80 字符                                               |
| 基本 | 指令          | 必填，1-20,000 字符                                           |
| 运行 | 对话策略      | `new_thread` 或 `continue_thread`；默认 `new_thread`          |
| 运行 | 来源 Thread   | 从对话创建时记录 provenance；继续模式必填                     |
| 运行 | 项目/工作目录 | 可为空；若选中必须解析为 current project owner                |
| 运行 | 模型          | `inherit` 或 stable model id；不存展示名作为 identity         |
| 运行 | 推理档位      | `inherit/low/medium/high/xhigh`，按模型能力裁剪               |
| 运行 | 权限模式      | `read_only/current/full_access`，默认继承创建上下文后冻结快照 |
| 频率 | 日程          | hourly/daily/weekdays/weekly                                  |
| 频率 | 时区          | IANA timezone；默认系统时区，必须显式落盘                     |
| 通知 | 规则          | `never/failures/all_runs`；P0 走 Desktop Host 系统通知        |
| 状态 | 启用          | 默认 true                                                     |

### 5.4 日程语义

| 类型       | 字段                                   | 例子                  |
| ---------- | -------------------------------------- | --------------------- |
| `hourly`   | `intervalHours`、可选 `days`、锚点分钟 | 每 2 小时，周一/三/五 |
| `daily`    | `time`                                 | 每天 09:00            |
| `weekdays` | `time`                                 | 工作日 08:00          |
| `weekly`   | `days`、`time`                         | 每周五 16:00          |

- `time` 使用本地 `HH:mm`，结合任务 `timezone` 计算。
- DST 跳时：不存在的本地时间顺延到下一合法时刻；重复时间仅执行一次。
- 设备休眠/离线：P0 每个任务最多补跑一次最近错过窗口，超过 24 小时不补跑，并在详情显示“错过运行”。
- 编辑日程后立即重算 next run；不会追补编辑前窗口。

### 5.5 详情与历史

- 详情顶部显示状态、名称、prompt、更多菜单、暂停/恢复动作。
- 基本信息和频率使用行式编辑，避免卡片套卡片。
- 历史默认最近 20 条，支持继续加载。
- 历史项显示 startedAt、duration、status、摘要和 Thread/Turn 链接。
- 运行中项可打开 live Thread；P0 不在任务详情复制一套消息流。

## 6. 状态模型

任务状态与运行状态分离：

| 对象 | 状态                                                                                            |
| ---- | ----------------------------------------------------------------------------------------------- |
| Task | `enabled / paused / needs_attention`                                                            |
| Run  | `queued / running / waiting_for_approval / completed / failed / timed_out / cancelled / missed` |

规则：

- `needs_attention` 是 Task 的派生状态：最近运行失败/超时/等待人工，或配置失效。
- 暂停中的任务不会自动运行，但允许“立即运行”。
- 同一任务默认并发策略为 `skip_if_running`；到期时已有运行则记录 missed/overlap reason，不并发启动第二次。
- 删除任务前必须确认；P0 软删除任务定义，历史 Thread/Run 保留并可追溯。

## 7. 错误与恢复

| 错误              | 用户可行动结果                                |
| ----------------- | --------------------------------------------- |
| 项目/目录不存在   | 标记需处理，提供重新选择项目                  |
| 模型不可用        | 标记需处理，提供改为继承/选择模型             |
| 权限需要人工确认  | 运行进入等待人工；通知用户并可打开 Thread     |
| Provider/网络失败 | 按 runtime retry policy；最终失败展示错误分类 |
| 应用退出/系统休眠 | 重启后按补跑政策处理，不静默丢失              |
| 任务已在运行      | 跳过本窗口并记录原因                          |

## 8. 非目标

- 云端 7x24 托管执行。
- 多设备同步与冲突合并。
- webhook、Telegram、Google Sheets 等通用投递编排。
- 秒级轮询、任意 Cron 编辑器、复杂节假日日历。
- 任务依赖 DAG、链式 workflow、批量编辑。
- 任务市场或 Plugin scheduled task 一键安装。

这些能力必须由后续需求单独立项，不能借 P0 字段预埋半成品 UI。

## 9. 成功指标

- 创建成功率 >= 95%（进入创建流程后成功落盘）。
- 到期触发与预期窗口偏差 P95 <= 60 秒（应用在线）。
- 重启后 next-run 恢复正确率 100%。
- 每个 completed/failed run 的 Thread/Turn 可追溯率 100%。
- 生产 mock 命中数 0，重复执行数 0。
