# 已安排任务交互与页面状态

状态：`normative UX`

## 1. 页面类型与设计原则

页面属于“列表工作台 + 主从详情”，不是设置表单页，也不是营销型首页。

- 当前主对象始终是选中的 Task。
- 当前阶段由 Task 状态和最近 Run 表达。
- 下一步动作始终是创建、修复配置、打开运行或暂停/恢复之一。
- 使用实体白色/浅灰表面、边框和留白，不使用半透明主面板、渐变大卡或卡片套卡片。
- 列表宽度保持约 `360-420px`；详情自适应剩余宽度，正文最大宽度约 `1200px`。
- 中文不加 tracking；按钮与行高稳定，长标题截断并提供 tooltip。

## 2. 成套原型契约

五张参考截图共同描述一条连续工作流，不得拆成五套独立信息架构。后续设计稿、GUI 实现和 E2E fixture 统一遵循以下合同：

| 维度 | 固定内容 |
| --- | --- |
| 目标用户 | 需要把已跑通工作交给 Lime 定期执行的桌面端用户 |
| 用户目标 | 创建任务、确认何时和在哪里运行、观察结果、处理失败 |
| 页面骨架 | 保留 Lime Desktop 窗口 chrome 与左侧主导航；“已安排任务”为一级入口；内容区在目录态和主从详情态之间切换 |
| 核心对象 | 已安排任务、运行、对话；默认 UI 不使用 AutomationJob、payload、scheduler、RuntimeCore 等工程名 |
| 统一主动作 | 目录态为“创建”；编辑态为“创建”或“保存”；运行中为“打开运行”；失败态为对应的单一修复动作 |
| 状态词表 | 已启用、已暂停、运行中、等待处理、已完成、失败、错过运行 |
| 视觉锚点 | 浅色实体表面、深海军蓝主按钮、浅青绿选中态、柔和绿色成功、琥珀提醒、红色问题态 |
| 禁止项 | 不重做 Lime 导航体系，不做营销 Hero，不用半透明主面板，不堆卡片，不在任务详情复制聊天消息流 |

统一用户旅程：

```text
进入任务目录
  -> 搜索/筛选或选择建议任务
  -> 使用 Lime 创建 / 手动设置
  -> 检查标题、指令、运行上下文和日程
  -> 用户确认后创建
  -> 查看任务详情和下一次运行
  -> 打开运行对应的真实对话
  -> 必要时修复、暂停、恢复、编辑或删除
```

参考截图只约束可见的信息架构、动作和状态关系；Lime 壳、五语种、RuntimeCore 主链、平台能力与失败治理以本路线合同为准，不做像素级照搬，也不臆测截图产品的内部实现。

## 3. 一级目录态

首次进入且未选中任务时：

```text
                  已安排的任务                       [创建 v]
                  让 Lime 按计划继续工作

                  [搜索已安排任务________________]
                  [全部] [已启用] [已暂停]

                  ○ 每日简报
                    工作日 08:00 · 下次今天 08:00

                  建议
                  每周回顾   每周五 16:00
                  跟进监控   工作日 09:00
```

大窗口采用居中窄列；进入任务后切换为主从布局。列表切换不能导致侧边栏或标题跳动。

## 4. 创建菜单

“创建”是深色主按钮，菜单只含两个动作：

- 对话图标 + 使用 Lime 创建
- 编辑图标 + 手动设置

选择“使用 Lime 创建”后进入新对话，composer 预置创建意图但不自动发送：

> 我们一起设置一个已安排任务。先说明它在 Lime 中的工作方式，再问我需要安排什么以及何时运行。

Agent 不能直接创建。它必须产出 `scheduled_task_draft` 结构化对象，并显示“检查并创建”；用户确认后调用 typed create method。

## 5. 手动创建/编辑态

详情面板右上角有关闭图标，底部固定主按钮；内容按三段组织：

1. 基本：标题、指令。
2. 运行于：对话策略、项目、模型、推理、权限。
3. 频率：重复、日期/星期、时间、时区、通知。

交互规则：

- 新建时标题为“新建”；编辑时显示任务状态和名称。
- 表单字段 blur 后校验；保存时服务端再校验。
- 未保存关闭需二次确认。
- 保存成功后保留在详情，不跳回目录；列表摘要与 next run 原地更新。
- 创建按钮只有一次主动作；高级字段收进“更多运行设置”，P0 默认折叠。

## 6. 已有任务详情态

```text
[启用]  每日简报                              [...] [暂停] [关闭]

给我一份晨间简报，包含日程、重要未读消息和今日事项。

详情
运行于      新聊天
项目        lime
模型        继承当前默认
推理        高
权限        按需确认

频率
重复        工作日
时间        08:00
时区        Asia/Shanghai
通知        所有运行

运行历史                                      [...]
○ 每日简报   运行中              1 分钟前
● 每日简报   已完成              2 天前
```

- 行式字段右侧使用下拉/选择器；详情浏览态不显示文本输入框边框。
- 更多菜单包含：立即运行、编辑、复制任务、删除。
- 运行中时主动作是“打开运行”；避免同时展示多个进度入口。
- 失败时状态区展示单一修复动作，例如“重新选择模型”。

## 7. 响应式策略

- `>= 1100px`：主从双栏。
- `720-1099px`：列表 `320px` + 详情；详情行可换行。
- `< 720px`：列表与详情路由式切换，详情顶部提供返回按钮；创建表单单列。
- 不使用 viewport font scaling；按钮、状态点、行高保持固定尺寸。

## 8. 完整状态表

| 场景       | 页面反馈                 | 可用动作                      |
| ---------- | ------------------------ | ----------------------------- |
| 初次加载   | 列表骨架，不显示假数据   | 无                            |
| 加载失败   | 就地错误 + 重试          | 重试                          |
| 空列表     | 简短空态 + 创建          | 创建                          |
| 搜索无结果 | 显示查询词 + 清空筛选    | 清空                          |
| 新建保存中 | 主按钮 spinner，表单锁定 | 取消不可用                    |
| 运行中     | 状态点 + 打开运行        | 打开、取消（若 runtime 支持） |
| 等待审批   | 明确阻塞原因             | 打开对话处理                  |
| 配置失效   | `需处理`                 | 修复配置                      |
| 已暂停     | 保留详情和历史           | 恢复、立即运行                |
| 删除中     | 确认弹窗                 | 取消、删除                    |

## 9. 可访问性

- 所有图标按钮有可读 `aria-label` 和 tooltip。
- 状态不能只靠颜色，必须有文字。
- 菜单、筛选、详情行和确认弹窗支持键盘操作与焦点返回。
- 动态运行状态通过低频 `aria-live="polite"` 通知，流式消息不在此页面重复播报。
- 对比度满足 WCAG AA。

## 10. 多语言

所有用户可见文案必须同时覆盖：

- `zh-CN`
- `zh-TW`
- `en-US`
- `ja-JP`
- `ko-KR`

日程摘要由结构化 formatter 生成，不在组件里拼接中文；weekday、日期、时间和相对时间使用 locale-aware API。
